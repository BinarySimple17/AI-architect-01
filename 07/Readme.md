## К расчёту инфраструктуры и стоимости инференса Llama-3-70b

### 1. Допущения
- Средняя длина **входного** запроса — 1024 токена.
- Средняя длина **выходного** ответа — 200 токенов.
- Итоговый пропускной режим: 1000 RPM ≈ 16,67 RPS, что даёт общую потребность в генерации примерно **2404 токена/с**.
- Батчинг использовался как способ утилизации GPU: для статического режима взят **batch size = 64** (группировка независимых запросов).
- Для расчётов применялись открытые калькуляторы VRAM и ориентировочные данные по производительности A100 (80 ГБ), T4 (16 ГБ) и L4 (24 ГБ).

### 2. Расчёт VRAM
**Результаты по памяти:**
| Компонент | FP16 (ГБ) | INT4 (ГБ) |
|-----------|-----------|-----------|
| Веса модели | 140 | 35 |
| KV-cache (на 64 запроса) | 25 | 25 |
| Overhead (15%) | 25 | 7 |
| **Итого VRAM** | **≈190** | **≈67** |

**Вывод по количеству GPU:**
- Для FP16 требуется минимум **3 × A100 80 ГБ** (по VRAM), но из-за производительности — гораздо больше.
- Для INT4 достаточно **1 × A100 80 ГБ** по памяти, но для 1000 RPM нужно уже несколько карт из-за скорости инференса.
- T4 и L4 **не рассматриваются как рабочие** – даже в INT4 модель не помещается на одну карту, а кластер из 5–8 таких GPU даёт крайне низкую пропускную способность (единицы токенов/с), что делает их экономически бессмысленными.

### 3. Оценка производительности (без оптимизаций)
Базовые измерения (batch=1) показали:
- **FP16 на 8×A100** → ~230 токен/с,
- **INT4 на 8×A100** → ~450 токен/с,
- **INT4 на 8×T4** → ~6 токен/с,
- **INT4 на 8×L4** → ~14 токен/с.

Для достижения 2404 токен/с **без оптимизаций** потребовалось бы:
- FP16: 89 узлов по 8 A100 = **712 GPU**,
- INT4: 46 узлов по 8 A100 = **368 GPU**,
- T4/L4 – тысячи GPU, что абсурдно.

Такой подход неприемлем ни по стоимости, ни по сложности.

---

### 4. Влияние оптимизаций (батчинг + vLLM)

в калькуляторе смоделировал два сценария:

| Сценарий | Throughput для FP16 (2×A100) | Throughput для INT4 (1×A100) | Требуемое кол-во GPU (FP16 / INT4) |
|----------|-------------------------------|-------------------------------|-------------------------------------|
| Без оптимизаций (batch=1) | 21 токен/с | 23 токен/с | 1756 / 878 |
| Статический батчинг (batch=64) | ~1344 токен/с | ~1472 токен/с | 32 / 14 |
| vLLM (cont. batching + PagedAttention, +100% к пропуску) | ~2688 токен/с | ~2944 токен/с | **16 / 7** |

**Ключевые эффекты vLLM:**
- PagedAttention повышает эффективность использования VRAM до 90% (против 20–40% в наивных подходах).
- Continuous Batching поднимает утилизацию GPU с ~50% до >90%, что даёт **1,5–2‑кратный прирост** относительно статического батчинга.
- В итоге для FP16 нужно 16 GPU A100, для INT4 – всего **7 GPU A100**.

### 5. Сравнение стоимости облаков (месяц)

Мы сравнили два провайдера (условно «Яндекс Облако» и «Selectel»):

| Конфигурация | Кол-во A100 | Яндекс Облако (тыс. руб/мес) | Selectel (тыс. руб/мес) |
|--------------|-------------|------------------------------|--------------------------|
| FP16 + vLLM  | 16          | 5 440                        | 3 876                    |
| INT4 + vLLM  | 8           | 2 720                        | **1 938**                |

Selectel даёт ощутимо более низкую цену при одинаковой конфигурации, поэтому в расчётах фигурирует как предпочтительный вариант. Хотя яндекс предлагает EPYC с 200+ ядрами и почти 1Тб RAM и поменять никак. Так что сранение цен условное.

### 6. Итоговая рекомендация
В итоге, с учетом всей условности расчетов

**Рекомендуемая конфигурация:**
- **Модель:** Llama-3-70b в **INT4** (квантование).
- **Сервер:** **8 × NVIDIA A100 80GB** (это с запасом, так как по расчётам достаточно 7 GPU, но кластер из 8 даёт резерв по отказоустойчивости и пиковым нагрузкам).
- **Оптимизации:** обязательное использование **vLLM** с Continuous Batching и PagedAttention.
- **Облачный провайдер:** Selectel.
- **Месячная стоимость:** ≈ **1 938 тыс. руб./мес.**

**Обоснование:**
- INT4 даёт выигрыш по памяти в 4 раза без существенной потери качества для большинства бизнес-задач.
- vLLM позволяет снизить количество GPU с 46 (в статическом режиме) до 7–8, сокращая затраты в 5–6 раз.
- Отказ от T4/L4 обусловлен катастрофически низкой пропускной способностью – их использование привело бы к неоправданно высоким расходам на парк машин.
