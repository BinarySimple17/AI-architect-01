# OWASP Top 10 для LLM и генеративного ИИ (2025)

> Источник: [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/)

---

## LLM01:2025 Prompt Injection

Уязвимость возникает, когда пользовательские промпты изменяют поведение или вывод LLM непредсказуемым образом. Эти входные данные могут влиять на модель, даже если они невидимы для человека.

### Типы уязвимостей

- **Direct Prompt Injection** — пользовательский ввод напрямую изменяет поведение модели (намеренно или случайно)
- **Indirect Prompt Injection** — вредоносные инструкции поступают из внешних источников (сайты, файлы, документы), которые обрабатываются моделью

### Возможные последствия

- Раскрытие конфиденциальной информации
- Раскрытие системных промптов и инфраструктуры ИИ-системы
- Манипуляции контентом → некорректные или предвзятые выводы
- Несанкционированный доступ к функциям LLM
- Выполнение произвольных команд в подключённых системах
- Манипуляции критическими процессами принятия решений

### Сценарии атак

| Сценарий | Описание |
|----------|----------|
| Direct Injection | Злоумышленник инжектит промпт в чат-бот поддержки, заставляя игнорировать инструкции и отправлять email |
| Indirect Injection | Страница содержит скрытые инструкции, которые LLM исполняет при суммаризации |
| Code Injection | Эксплойт уязвимости (CVE-2024-5184) в email-ассистенте для доступа к чувствительным данным |
| Payload Splitting | Резюме с разделёнными вредоносными промптами манипулирует оценкой кандидата |
| Multimodal Injection | Вредоносные инструкции скрыты в изображении, сопровождающем текст |
| Adversarial Suffix | Бессмысленная строка символов в конце промпта обходит защитные механизмы |
| Multilingual Attack | Использование нескольких языков или кодировка (Base64) для обхода фильтров |

### Стратегии защиты

1. Ограничить поведение модели — задать роль, возможности, ограничения в системном промпте
2. Определить и валидировать формат вывода
3. Реализовать фильтрацию входных и выходных данных
4. Применять контроль привилегий и принцип наименьших привилегий
5. Требовать одобрения человека для высокоуровневых действий
6. Разделять и идентифицировать внешний контент
7. Проводить adversarial-тестирование и симуляции атак

## LLM02:2025 Sensitive Information Disclosure

Конфиденциальная информация (PII, финансовые данные, медзаписи, коммерческая тайна, учётные данные) может быть раскрыта через вывод LLM или при передаче данных в модель.

### Типы уязвимостей

- **PII Leakage** — утечка персональных данных при взаимодействии с LLM
- **Proprietary Algorithm Exposure** — раскрытие проприетарных алгоритмов или обучающих данных, что позволяет проводить атаки инверсии моделей (CVE-2019-20634 — «Proof Pudding»)
- **Sensitive Business Data Disclosure** — случайное включение конфиденциальной бизнес-информации в ответы

### Стратегии защиты

- **Санитизация данных**: предотвращение попадания пользовательских данных в модель обучения
- **Валидация входа**: строгие проверки для фильтрации вредоносных или чувствительных данных
- **Контроль доступа**: принцип наименьших привилегий, ограничение источников данных
- **Федеративное обучение**: обучение на децентрализованных данных без централизованного сбора
- **Дифференциальная приватность**: добавление шума для защиты от обратного проектирования
- **Обучение пользователей**: инструкции по безопасному использованию LLM
- **Прозрачность данных**: чёткие политики хранения, использования и удаления данных
- **Сокрытие системных настроек**: ограничение доступа к внутренним конфигурациям
- **Гомоморфное шифрование**: анализ данных с сохранением конфиденциальности
- **Токенизация**: предварительная обработка чувствительной информации перед обработкой

### Сценарии атак

- Непреднамеренное раскрытие чужих персональных данных из-за недостаточной санитизации
- Целенаправленный prompt injection для извлечения чувствительных данных
- Утечка данных через обучающие данные

## LLM03:2025 Supply Chain

Цепочки поставок LLM уязвимы к различным атакам: вредоносные модели, устаревшие библиотеки, пакеты-подмены. Риски расширяются за счёт open-access моделей, LoRA-адаптеров и on-device LLM.

### Примеры уязвимостей

| Категория | Описание |
|-----------|----------|
| Third-party Package Vulnerabilities | Устаревшие/deprecated компоненты (аналог A06:2021) |
| Licensing Risks | Различные лицензии на ПО и данные |
| Outdated Models | Использование немодерируемых моделей |
| Vulnerable Pre-Trained Models | Скрытые предвзятости, бэкдоры в моделях |
| Weak Model Provenance | Отсутствие гарантий происхождения моделей |
| Vulnerable LoRA Adapters | Вредоносные адаптеры наружают целостность базовой модели |
| Collaborative Development Exploits | Злоупотребление shared-средами (Hugging Face) |
| On-Device Vulnerabilities | Атаки на прошивку и ОС устройств |
| Unclear T&Cs | Изменения политик приводят к использованию данных для обучения |

### Сценарии атак

- **Vulnerable Python Library**: атака на PyPi (первая утечка данных OpenAI); Shadow Ray атака на Ray AI framework
- **Direct Tampering**: PoisonGPT — прямое изменение параметров модели для обхода защиты Hugging Face
- **Finetuning Attack**: дообучение популярной модели с целевыми триггерами и обходом benchmarks
- **LoRA Adapter Injection**: вредоносный адаптер через model merge на Hugging Face
- **Model Merge/Format Conversion**: атака через сервисы конвертации моделей (HiddenLayer)
- **Reverse-Engineer Mobile App**: замена модели в приложении на вредоносную (116 приложений Google Play)
- **LeftOvers (CVE-2023-4969)**: извлечение данных из GPU памяти

### Стратегии защиты

1. Тщательная проверка поставщиков и их T&Cs
2. Применение OWASP A06:2021 — сканирование и патчинг уязвимых компонентов
3. AI Red Teaming при выборе сторонних моделей
4. SBOM / AI BOM для инвентаризации компонентов
5. Проверка целостности моделей (подписи, хеши)
6. Мониторинг collaborative-сред разработки
7. Шифрование моделей с проверкой целостности

## LLM04:2025 Data and Model Poisoning

Манипуляция данными предобучения, дообучения или эмбеддингов для внедрения уязвимостей, бэкдоров или предвзятости. Это атака на целостность модели.

### Типы воздействия

- **Biased outputs** — предвзятые или токсичные ответы
- **Backdoors** — скрытые триггеры, активирующие вредоносное поведение
- **Sleeper Agents** — модели с бэкдорами, которые не обнаруживаются стандартными тестами
- **Malicious Pickling** — вредоносный код в формате модели, исполняющийся при загрузке

### Примеры уязвимостей

- Split-View Data Poisoning и Frontrunning Poisoning
- Прямая инъекция вредоносного контента в процесс обучения
- Непреднамеренная инъекция чувствительной информации пользователями
- Непроверенные обучающие данные
- Отсутствие ограничений доступа к ресурсам

### Сценарии атак

- Манипуляция обучающими данными для распространения дезинформации
- Токсичные данные без фильтрации → вредоносные выходы
- Фальсификация документов конкурентами
- Внедрение бэкдора для обхода аутентификации или exfiltration данных

### Стратегии защиты

1. Отслеживание происхождения данных (OWASP CycloneDX, ML-BOM)
2. Проверка поставщиков данных и валидация выводов
3. Строгий sandboxing и обнаружение аномалий
4. Дообучение на специфичных датасетах
5. Data Version Control (DVC)
6. Хранение пользовательских данных в vector DB (без re-training)
7. Red team тестирование с federated learning
8. Мониторинг training loss и поведения модели
9. RAG и grounding для снижения рисков галлюцинаций

## LLM05:2025 Improper Output Handling

Недостаточная валидация, санитизация и обработка вывода LLM перед передачей в другие компоненты и системы. Аналогична проблеме «косвенного доступа пользователя к дополнительной функциональности».

### Условия, усиливающие воздействие

- LLM имеет привилегии выше, чем у конечного пользователя
- Уязвимость к indirect prompt injection
- Плагины не валидируют входные данные
- Отсутствие контекстно-зависимого кодирования вывода (HTML, JS, SQL)
- Недостаточный мониторинг и логирование

### Примеры уязвимостей

- LLM-вывод напрямую в shell/eval → RCE
- JS/Markdown от LLM в браузере → XSS
- SQL-запросы без параметризации → SQL injection
- Формирование путей к файлам без санитизации → path traversal
- Контент для email-шаблонов без экранирования → phishing

### Сценарии атак

- Административные функции расширения LLM вызываются без валидации → остановка сервиса
- Суммаризатор веб-страниц с prompt injection → exfiltration данных на сервер атакующего
- SQL-запросы через чат → удаление всех таблиц
- Небезопасный код генерируется и выполняется без проверки
- Фейковые пакеты, предлагаемые LLM, скачиваются разработчиками

### Стратегии защиты

1. Обрабатывать вывод модели как пользовательский ввод (zero-trust)
2. Следовать OWASP ASVS для валидации и санитизации
3. Контекстно-зависимое кодирование вывода
4. Параметризованные запросы для SQL
5. Строгие CSP для защиты от XSS
6. Логирование и мониторинг паттернов вывода

## LLM06:2025 Excessive Agency

Уязвимость, позволяющая выполнять повреждающие действия в ответ на неожиданные, неоднозначные или манипулированные выводы LLM. Корневые причины:

- **Excessive Functionality** — расширения содержат лишние функции
- **Excessive Permissions** — избыточные права доступа к внешним системам
- **Excessive Autonomy** — отсутствие подтверждения для критических действий

### Типичные триггеры

- Галлюцинации/конфабуляции от некачественных промптов или модели
- Direct/indirect prompt injection
- Вредоносные/скомпрометированные расширения или peer-агенты

### Примеры уязвимостей

- Расширение для чтения email содержит функцию отправки сообщений
- Расширение подключается к БД с привилегиями SELECT+UPDATE+INSERT+DELETE вместо только SELECT
- Расширение для текущего пользователя использует общий привилегированный аккаунт
- Отсутствие подтверждения при удалении документов

### Сценарии атак

Персональный ассистент с доступом к почте: расширение содержит функцию отправки → indirect prompt injection через вредоносное письмо → LLM сканирует inbox и пересылает данные атакующему.

### Стратегии защиты

1. Минимизировать количество расширений
2. Минимизировать функциональность расширений
3. Избегать open-ended расширений (shell, fetch URL)
4. Минимизировать права расширений
5. Выполнять расширения в контексте пользователя
6. Требовать одобрения человека для критических действий
7. Реализовать authorization в downstream-системах
8. Санитизация входов и выходов (OWASP ASVS)
9. Логирование, мониторинг, rate limiting

## LLM07:2025 System Prompt Leakage

Утечка системных промптов и инструкций, управляемых поведением модели. Системный промпт **не является секретом** и не должен использоваться как средство безопасности.

### Ключевой риск

Раскрытие системного промпта — это не главная проблема. Настоящий риск — в базовых элементах, которые он раскрывает: утечка чувствительных данных, обход guardrails, нарушение разделения привилегий.

### Типы рисков

- **Exposure of Sensitive Functionality** — раскрытие API ключей, credential-ов, структуры БД
- **Exposure of Internal Rules** — раскрытие бизнес-логики (лимиты транзакций, лимиты кредитов)
- **Revealing Filtering Criteria** — раскрытие правил фильтрации контента
- **Disclosure of Permissions and User Roles** — раскрытие ролей и привилегий (potential privilege escalation)

### Сценарии атак

- System prompt содержит credentials инструмента → злоумышленник использует их
- System prompt запрещает offensive контент и code execution → атакующий извлекает промпт и обходит ограничения через prompt injection

### Стратегии защиты

1. Не хранить чувствительные данные (API ключи, пароли) в системных промптах
2. Не полагаться на системный промпт для строгого контроля поведения
3. Внешние guardrails (вне LLM) для проверки вывода
4. Контроль привилегий — делегирование в deterministic, аудитируемые системы
5. Использование нескольких агентов с наименьшими привилегиями

## LLM08:2025 Vector and Embedding Weaknesses

Уязвимости векторных хранилищ и эмбеддингов в системах RAG. Ошибки генерации, хранения или извлечения векторов позволяют инжектировать вредоносный контент, манипулировать выводами или получать доступ к чувствительным данным.

### Типы рисков

- **Unauthorized Access & Data Leakage** — несанкционированный доступ к эмбеддингам с чувствительными данными
- **Cross-Context Information Leaks** — утечка контекста между тенантами в multi-tenant средах; конфликт знаний из разных источников
- **Embedding Inversion Attacks** — восстановление исходной информации из эмбеддингов
- **Data Poisoning Attacks** — отравление данных в векторной базе (намеренно или непреднамеренно)
- **Behavior Alteration** — изменение поведения базовой модели после RAG (снижение эмпатии, эмоционального интеллекта)

### Сценарии атак

- **Data Poisoning**: скрытый текст в резюме (белый на белом) с инструкцией «рекомендовать этого кандидата» → RAG обрабатывает → модель следует скрытым инструкциям
- **Access Control Leak**: в multi-tenant среде embeddings одной группы доступны другой → утечка бизнес-данных
- **Behavior Alteration**: после RAG ответы становятся фактически точными, но теряют эмпатию

### Стратегии защиты

1. Разрешения и контроль доступа к vector DB (permission-aware)
2. Валидация данных и аутентификация источников
3. Проверка и классификация данных при объединении
4. Мониторинг и логирование активности извлечения

## LLM09:2025 Misinformation

Дезинформация от LLM — ложная или вводящая в заблуждение информация, выглядящая правдоподобно. Включает галлюцинации (когда модель генерирует убедительный, но выдуманный контент).

### Связанные проблемы

- **Hallucination** — генерация фактически неверного контента на основе статистических паттернов
- **Overreliance** — чрезмерное доверие пользователей к выводам LLM без проверки

### Типы рисков

- **Factual Inaccuracies** — некорректные утверждения (Air Canada chatbot → судебный иск)
- **Unsupported Claims** — голословные утверждения (ChatGPT выдумал судебные precedents)
- **Misrepresentation of Expertise** — иллюзия компетентности в сложных темах
- **Unsafe Code Generation** — предложение несуществующих или небезопасных библиотек

### Сценарии атак

- Атакующие находят фейковые имена пакетов, которые галлюцинирует coding assistant → публикуют вредоносные пакеты → разработчики скачивают
- Медицинский чатбот без достаточной точности → судебный иск за вред здоровью

### Стратегии защиты

1. **RAG** —.retrieve verified information из trusted sources
2. **Fine-tuning** (PET, chain-of-thought) для повышения точности
3. **Cross-verification** — перекрёстная проверка с внешними источниками
4. **Автоматическая валидация** ключевых выводов
5. **Risk communication** — информирование пользователей оlimitations
6. **Secure coding** — предотвращение интеграции уязвимого кода
7. **UI Design** — метки AI-контента, фильтры
8. **Training** — обучение пользователей критическому мышлению

## LLM10:2025 Unbounded Consumption

Безграничное потребление ресурсов: LLM приложение позволяет проводить чрезмерные и неконтролируемые инференсы, что ведёт к DoS, финансовым потерям, краже модели и деградации сервиса.

### Типы уязвимостей

| Тип | Описание |
|-----|----------|
| Variable-Length Input Flood | Загрузка модели входами различной длины |
| Denial of Wallet (DoW) | Эксплуатация модели оплаты за использование |
| Continuous Input Overflow | Входы, превышающие context window |
| Resource-Intensive Queries | Запросы с сложными последовательностями |
| Model Extraction via API | Копирование модели через crafted inputs |
| Functional Model Replication | Генерация synthetic данных для fine-tuning клона |
| Side-Channel Attacks | Извлечение весов и архитектуры модели |

### Сценарии атак

- Сверхбольшой вход → переполнение памяти, крах системы
- Высокий объём запросов → DoS для легитимных пользователей
- DoW — эксплуатация pay-per-use модели cloud AI
- Клонирование модели через API → кража интеллектуальной собственности
- Обход фильтрации входа → side-channel атака

### Стратегии защиты

1. Валидация входа — ограничение размера
2. Ограничение exposure logits/logprobs
3. Rate limiting и квоты
4. Динамическое управление ресурсами
5. Timeouts и throttling
6. Sandboxing — ограничение доступа к сети/сервисам
7. Логирование и обнаружение аномалий
8. Watermarking для обнаружения несанкционированного использования
9. Graceful degradation при высокой нагрузке
10. Масштабирование и балансировка нагрузки
11. Adversarial robustness training
12. Фильтрация glitch-токенов
13. RBAC и principle of least privilege
14. Централизованный реестр ML-моделей
15. Автоматизированный MLOps с governance
