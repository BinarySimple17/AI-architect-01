# Оценка качества RAG

## 1. Метрики RAG

>Пороговые значения взяты из никаких соображений. Потом установить после пилотного прогона на реальных данных

### Retrieval-метрики (качество поиска в Qdrant)

| Метрика | Описание | Инструмент | Целевое значение |
|---------|----------|------------|------------------|
| **Recall@k** | Доля релевантных документов, попавших в top_k | Ragas (Context Recall) | ≥ 0.85 |
| **Precision@k** | Доля релевантных среди возвращённых | Ragas (Context Precision) | ≥ 0.70 |
| **Context Precision** | Средняя точность контекста с учётом порядка | Ragas | ≥ 0.75 |
| **Context Recall** | Покрытие ground-truth найденными документами | Ragas | ≥ 0.80 |
| **Triplet Accuracy** | Доля корректно ранжированных троек (запрос, позитив, негатив) | Кастомный скрипт | ≥ 0.90 |

### Generation-метрики (качество ответа LLM)

| Метрика | Описание | Инструмент | Целевое значение |
|---------|----------|------------|------------------|
| **Faithfulness** | Ответ основан только на извлечённом контексте | Ragas | ≥ 0.85 |
| **Answer Relevancy** | Ответ релевантен запросу | Ragas | ≥ 0.80 |
| **Answer Correctness** | Фактическая точность по сравнению с ground-truth | Ragas | ≥ 0.75 |
| **Hallucination Rate** | Доля утверждений, не подкреплённых контекстом (1 – Faithfulness) | Ragas | ≤ 0.15 |

### Дедупликация

| Метрика | Описание | Инструмент | Целевое значение |
|---------|----------|------------|------------------|
| **Dedup Precision** | Доля реальных дубликатов среди отмеченных | Кастомный скрипт | ≥ 0.90 |
| **Dedup Recall** | Доля обнаруженных реальных дубликатов | Кастомный скрипт | ≥ 0.80 |
| **Dedup F1** | Гармоническое среднее Precision и Recall | Кастомный скрипт | ≥ 0.85 |

## 2. Инструменты

### Ragas — глубокая оценка RAG-пайплайна

- **Назначение:** оценка качества retrieval и generation на golden set.
- **Установка:** `pip install ragas`
- **Метрики:** Faithfulness, Answer Relevancy, Context Precision, Context Recall, Answer Correctness.
- **LLM-as-Judge:** использует Qwen on‑prem для оценки утверждений. Рекомендуется ежемесячная ручная выборочная проверка для калибровки.
- **Формат данных:** Dataset: `question`, `answer`, `contexts`, `ground_truth`.
- **Интеграция:** `pytest tests/rag/ --ragas-report=report.json`.
- **Частота:** еженедельно + при изменении промптов/модели.
- **Артефакт:** JSON-отчёт с оценками.

### promptfoo — канареечные и регрессионные тесты (дополнительно)

- **Назначение:** быстрые gate-тесты перед деплоем, проверка безопасности и устойчивости.
- **Установка:** `npm install -g promptfoo`
- **Частота:** перед каждым деплоем (CI/CD gate).
- **Типы ассершенов:** `llm-rubric`, `contains`, `not-contains`, `is-json`, `regex`.
- **Канареечные промпты:** prompt leak, PII leak, toxicity, jailbreak, SQL injection, формат JSON, релевантность.

---

### Категории тестов

| Категория | Описание | Мин. кол-во |
|-----------|----------|-------------|
| **Happy Path** | Типичные запросы | 20 |
| **Edge Cases** | Неточные формулировки, опечатки, синонимы | 10 |
| **Multi-Result** | Запросы с несколькими релевантными решениями | 10 |
| **No Match** | Запросы без ответа в базе | 5 |
| **Per Direction** | Минимум 3 запроса на каждое направление поддержки | по 3 |

**Минимальный объём:** ≥ 50 записей. Хранится в Git: `tests/golden_set/golden_set.json`.

### Пополнение Golden Set
- **Ручное создание** — 30%.
- **Из успешных ответов AI** (администратор подтверждает через Thymeleaf) — 35%.
- **Из неудачных ответов AI** (администратор добавляет корректный ответ) — 20%.
- **Из закрытых обращений ERP** с высоким satisfaction score — 15%.
- Автоматическое пополнение кандидатов при `satisfaction_score ≥ 4.5` и подтверждении администратором.

### Неудачные ответы (failed cases)
Администратор может отметить ответ как неудачный с указанием причины (`hallucination`, `irrelevant`, `incomplete`, `outdated`, `toxic`, `pii_leak`). Записи сохраняются в `failed_cases.json` со статусами (`pending_analysis`, `analyzed`, `golden_set_added`, `prompt_fix_submitted`, `resolved`). Используются для улучшения golden set, тюнинга промптов, обучения guardrails и мониторинга дрейфа.

## 4. Критические точки для тестирования качества RAG

### Точка 1: Пополнение базы знаний (Embedding + Дедупликация)

| Что тестировать | Метод | Инструмент | Критерий успеха |
|----------------|-------|------------|-----------------|
| Качество эмбеддинга нового обращения | Юнит-тест | pytest | Вектор размерности 1024, cosine similarity с semantically близким > 0.7 |
| Корректность чанкинга решений | Юнит-тест | pytest | Каждый чанк ≤ 512 токенов, нет потери данных между чанками |
| Дедупликация: ложные срабатывания | Регрессионный тест | Ragas (кастомный) | Dedup Precision ≥ 0.90 |
| Дедупликация: пропуск дубликатов | Регрессионный тест | Ragas (кастомный) | Dedup Recall ≥ 0.80 |
| Порог дедупликации (cosine > 0.92) | Юнит-тест | pytest | При similarity 0.93 → pending, при 0.91 → уникальное |
| Качество эмбеддингов после обновления модели | Регрессионный тест | Ragas | Recall@k не ниже baseline > 5% |

### Точка 2: Семантический поиск (Retrieval Quality)

| Что тестировать | Метод | Инструмент | Критерий успеха |
|----------------|-------|------------|-----------------|
| Recall@k | Регрессионный тест | Ragas | ≥ 0.85 |
| Precision@k | Регрессионный тест | Ragas | ≥ 0.70 |
| Context Precision | Регрессионный тест | Ragas | ≥ 0.75 |
| Context Recall | Регрессионный тест | Ragas | ≥ 0.80 |
| Ранжирование: полные обращения vs чанки | Юнит-тест | pytest | Полные обращения (вес × 1.0) выше чанков (вес × 0.8) при равном score |
| Отсечение по similarity_threshold | Юнит-тест | pytest | Результаты с score < порога не возвращаются |
| Дедупликация результатов (чанк → решение уже есть) | Юнит-тест | pytest | Дублирующие чанки пропускаются |

### Точка 3: Генерация LLM (Answer Quality)

| Что тестировать | Метод | Инструмент | Критерий успеха |
|----------------|-------|------------|-----------------|
| Faithfulness | Регрессионный тест | Ragas | ≥ 0.85 |
| Answer Relevancy | Регрессионный тест | Ragas | ≥ 0.80 |
| Answer Correctness | Регрессионный тест | Ragas | ≥ 0.75 |
| Hallucination Rate | Регрессионный тест | Ragas | ≤ 0.15 |
| Качество после обновления промпта | Регрессионный тест | Ragas | Все метрики ≥ baseline |
| Качество после обновления модели | Регрессионный тест | Ragas | Все метрики ≥ baseline |

## 5. План тестирования (оценка RAG)

1. **Офлайн-оценка (Ragas)** – еженедельный прогон на golden set в период минимальной нагрузки. Проверяются все метрики (Faithfulness, Answer Relevancy, Context Precision, Context Recall). Гейт: все метрики ≥ целевых порогов. Артефакт: JSON-отчёт.
2. **Регрессионные тесты** – запускаются при изменении промптов, моделей, top_k, threshold. Используются Ragas + pytest.
3. **Мониторинг дрейфа** – ежемесячное сравнение распределения запросов в golden set с реальными запросами за последнюю неделю.
